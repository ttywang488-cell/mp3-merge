# merge-mp3.js — MP3 首尾相连合成新歌

把**同一文件夹**里的所有 `.mp3` 歌曲按文件名排序，首尾相连合成一个新 MP3。



## 便携版（可发给别人）

本文件夹已内置 Node 运行时（`runtime
ode.exe`）和 FFmpeg（`node_modulesfmpeg-static`），
**把整个文件夹（含 `runtime` 和 `node_modules`）打包成 zip 发给任何人**，对方无需安装任何东西，
解压后双击 `启动合成器.vbs` 即可使用。

> 注意：打包前删除 `服务.pid`（运行残留的进程记录文件，不影响使用）；
> 若 zip 太大可删掉 `test-full.js` 和 `README.md`（约 168MB → 主要体积来自 runtime 89MB + ffmpeg 80MB）。

## 可视化界面（推荐）


双击 **启动合成器.vbs**（无黑窗口）或 **启动合成器.bat**（显示日志窗口）：

1. 自动启动本地服务并打开浏览器界面；
2. 左侧浏览/粘贴歌曲文件夹路径，勾选歌曲（支持全选）；
3. 点击「📁 选择输出文件夹」选保存位置（选 C 盘根目录会自动提示并改为主目录），或点「➕ 新建文件夹」输入名称直接创建；
4. 选择「衔接方式」（直接拼接 / 淡出淡入 1-5 秒，淡出淡入为前一首淡出结束后后一首再淡入，不重叠）；
5. 点击「合成新歌曲」，先弹出命名框输入歌曲名（如"串烧"），确认后合成（输出文件若同名会自动加序号保存，不覆盖旧文件）。

命令行用法（无界面）:
```bash
node merge-mp3.js <歌曲文件夹路径> [输出文件.mp3] [--ffmpeg <ffmpeg.exe路径>]
```

## 用法

```bash
node merge-mp3.js <歌曲文件夹路径> [输出文件.mp3] [--ffmpeg <ffmpeg.exe路径>]
```

| 参数 | 说明 |
|---|---|
| `<歌曲文件夹路径>` | 必填，放 MP3 的文件夹 |
| `[输出文件.mp3]` | 可选，默认 `所选文件夹/merged.mp3` |
| `--ffmpeg <路径>` | 可选，指定系统 FFmpeg 可执行文件路径 |

示例：

```bash
# 最简用法，输出到歌曲文件夹里的 merged.mp3
node merge-mp3.js "D:\音乐\我的歌单"

# 指定输出文件
node merge-mp3.js "D:\音乐\我的歌单" "D:\音乐\串烧.mp3"
```

## 工作原理

1. 扫描文件夹内所有 `.mp3`，按文件名（中文友好排序）排列。
2. 逐文件解析 MPEG 帧头，提取 **MPEG 版本 / 层 / 采样率 / 声道 / 比特率**。
3. 决策：
   - **所有文件参数一致** → **无损直拼**：剥掉每个文件的 ID3v2 标签头、ID3v1/APEv2 标签尾，把音频帧原样首尾相连。速度快、零依赖、音质无损。
   - **参数不一致** → **自动回退 FFmpeg**：统一重采样/声道后重编码拼接（192kbps MP3），保证结果可正常播放。

## 依赖

- **无损路径**：仅需 Node.js（`node` 在 PATH 中），无任何 npm 依赖。
- **FFmpeg 回退路径**：需要 FFmpeg。按以下任一方式准备：
  1. `winget install Gyan.FFmpeg`（推荐，安装后自动被脚本发现）；
  2. 手动下载 [FFmpeg](https://ffmpeg.org/download.html)，用 `--ffmpeg` 指定路径；
  3. `npm install ffmpeg-static`（自动从 GitHub 拉取约 70MB 二进制，国内网络可能超时）。

> 当前目录已内置 `node_modules/ffmpeg-static`（ffmpeg.exe 6.1.1），FFmpeg 回退路径开箱即用。

## 说明与限制

- 无损直拼要求采样率、声道、MPEG 版本一致；**比特率不同可以混拼**（CBR/VBR 都行，因为每个 MP3 帧头自带比特率信息）。
- 无损拼接会去掉各文件的 ID3 标签，输出文件不带歌曲信息——如需保留标题，可用播放器或标签工具自行添加。
- 扫描会排除输出文件本身（避免把上次的合并结果再次拼进去）。
- 无法解析为 MP3 的文件会被跳过并提示。
